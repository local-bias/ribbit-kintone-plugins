# 06. 操作画面のUI仕様

## 1. 画面構成

```
                                                     ┌──────────────────────────┐
                                                     │  パネル                   │
                                                     │  ┌──────────────────────┐│
                                                     │  │ [JS] [CSS] [チャット] ││ ← タブ
                                                     │  ├──────────────────────┤│
                                                     │  │                      ││
                                                     │  │   選択中のビュー      ││
                                                     │  │                      ││
                                                     │  └──────────────────────┘│
                                                     └──────────────────────────┘
                                                                        ┌─────┐
   画面右下に常時見える起動ボタン                                →       │ 🐸  │
                                                                        └─────┘
```

## 2. ランチャー

### 起動ボタン

- 透明な `200px × 200px` ホットゾーンは採用しない。`pointer-events: none` では領域のhoverを検知できず、
  pointer eventを受けるとkintoneの操作を覆うため、要件を両立できない。
- 画面右下に44px以上のbuttonを常時表示し、通常時は不透明度0.45、hover / focus / パネル表示中は1にする。
- `prefers-reduced-motion` ではフェードや移動アニメーションを無効化する。
- kintoneの固定UIと重なる場合に備え、設定で右下 / 左下と余白を選べるようにする。

### アイコン

| 状態 | 見た目 |
| --- | --- |
| 通常 | 直径56pxの円。常時見える。ホバー / フォーカスで強調 |
| アセット適用中 | 適用件数のバッジ(小さな数字) |
| エラーあり(実行時エラー・権限外の操作を止めた・迂回パターンで未実行) | ⚠ バッジ(赤) |
| 読み込めなかった(起動ゲートのタイムアウト・取得失敗) | ⏱ バッジ(橙)。パネル上部に理由と再読み込みボタン(→ [05](./05-runtime.md) 2-1) |
| セーフモード | アイコンをグレースケール + ツールチップに「セーフモード」 |

### キーボード操作

- `button` 要素で実装し、Tabで到達できるようにする。フォーカス時はホバーと同じく可視化する。
- `Enter` / `Space` で開く、`Escape` で閉じる。
- `aria-label` は「kintoneカスタマイズ(ai-customize)を開く」。

## 3. メニュー

アイコンをクリックすると、アイコンの左上方向にメニューが開く。

| 項目 | 表示条件 | 遷移先 |
| --- | --- | --- |
| **JavaScript** `(n)` | 常時 | JS一覧 |
| **CSS** `(n)` | 常時 | CSS一覧 |
| **チャット** | チャット権限あり かつ AI設定済み | チャットパネル |
| セーフモードで再読み込み | 常時(メニュー下部のリンク) | `new URL(location.href)` の `searchParams.set` で既存queryを保って再読み込み |
| このアプリの設定を開く | アプリ管理権限あり | プラグイン設定画面 |

`(n)` は**適用中の件数**(無効・ローカル無効を除く)。

## 4. パネル

- サイズ: 幅 `min(480px, 100vw - 32px)`、高さ `min(640px, 100vh - 120px)`。右下から `24px` の余白。
- チャット時のみ、ドラッグで幅を広げられる(最大 `860px`)。`@repo/ui` の `resizable` を使う。
- `Escape` で閉じる。パネル外クリックでは**閉じない**(コードを書いている最中に消えると悲惨なため)。
- 開閉状態と選択中タブは `sessionStorage` に保存し、画面遷移をまたいで維持する。
- パネルをdialogとして扱い、開いたら見出しへフォーカスを移す。Tabはパネル内で循環させ、閉じたら起動ボタンへ戻す。
- 保存前の変更がある状態で閉じるときは確認する。ブラウザの画面遷移でも破棄警告を出す。
- 375pxでは左右16px、768px以上では右下24pxを基準にし、ボタン列と長い英語文言は折り返す。横スクロールを必須にしない。

## 5. JS / CSS 一覧

```
┌──────────────────────────────────────────────────┐
│ JavaScript                          [＋ 新規]     │
│ ┌──────────────────────────────────────────────┐ │
│ │ 保存前に金額をチェック            [全員]  ●─  │ │
│ │ #12 · 佐藤 · 3日前 · [更新]                   │ │
│ ├──────────────────────────────────────────────┤ │
│ │ 一覧に合計行を出す               [自分だけ] ●─ │ │
│ │ #18 · 自分 · 1時間前                          │ │
│ ├──────────────────────────────────────────────┤ │
│ │ ⚠ サブテーブル集計                [全員]  ─○  │ │
│ │ #21 · 田中 · 実行時エラー                     │ │
│ └──────────────────────────────────────────────┘ │
│ 適用中: 2件 / 全3件                    [再読み込み]│
└──────────────────────────────────────────────────┘
```

### 行の要素

| 要素 | 内容 |
| --- | --- |
| ドラッグハンドル | 行の左端。掴んで上下に動かすと実行順を入れ替えられる(後述) |
| タイトル | `title`。空なら「(無題)」 |
| 影響範囲バッジ | `自分だけ`(グレー) / `全員`(青)。クリックで変更(権限がある場合のみ) |
| 有効スイッチ | 後述 |
| 権限チップ | 付与済みの書き込み系権限(`追加` `更新` `削除` `外部: 2件` `外部: すべて`)。読み取りは常時なので出さない。`外部: すべて` と `制限なし` は警告色 + アイコン |
| メタ行 | `#レコードID · 所有者 · 相対更新日時`。エラー時はエラー要約 |
| 警告アイコン | 実行エラー / 権限外の操作を止めた / 迂回パターンのため未実行 / 適用画面外 / 設定不備 |

行をクリックすると詳細(コード表示)に遷移する。

### 実行順の並び替え(ドラッグ&ドロップ)

`order` フィールドの値を、数値入力ではなく**ドラッグで並べ替えて決める**。
CSSの適用順は実務で効くうえ、「どちらが後に来るか」は数値より並び順のほうが直感的に分かるため。

| 項目 | 仕様 |
| --- | --- |
| ライブラリ | `@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/modifiers`(リポジトリで既に使われている標準) |
| 対象 | JS一覧・CSS一覧それぞれの中で並べ替える。**種別をまたぐ並べ替えはしない** |
| 掴む場所 | 行左端のドラッグハンドルのみ(行全体を掴めるようにすると、開くつもりが動いてしまう) |
| 制約 | 縦方向のみ(`restrictToVerticalAxis`)、リスト内に限定(`restrictToParentElement`) |
| 保存 | ドロップ確定時に、**並び順が変わったレコードだけ** `order` を採番し直して更新する |
| 採番 | 先頭から `100, 200, 300, …` と振り直す。歯抜けを残さない(隙間採番は結局破綻する) |
| 更新方法 | `updateAllRecords` を使うが、複数APIに分割・部分成功しうる前提で扱う。**各レコードに `revision` を付けて楽観ロックする**(付けないと、他人が同時に触った内容を黙って上書きする) |
| 競合時 | revision不一致で失敗したら、部分的に成功したぶんも含めてサーバーを再取得し、「他の人が更新しました」と表示して並び順を作り直させる |
| 楽観的更新 | UI上は即座に並べ替える。失敗時は元配列へ戻すだけでなく、サーバーを再取得して確定状態を表示する |
| 権限 | **編集権限のないレコードが含まれる場合はドラッグを禁止**し、ハンドルを無効表示にする。理由をツールチップで説明 |
| 反映 | CSSは並べ替え後に `<style>` を並べ直して即時反映。JSは「再読み込みで反映されます」と表示 |
| キーボード操作 | `@dnd-kit` のキーボードセンサーを有効にし、ハンドルにフォーカスして矢印キーで移動できるようにする |

並べ替えの結果はレコードの `order` に書き込まれるため、**全員に影響する**。
自分だけ順序を変えることはできない(ローカル無効化のような仕組みは持たない)。この点はツールチップで説明する。

### 有効スイッチの挙動

| ユーザーの権限 | 操作結果 |
| --- | --- |
| そのレコードを編集できる | レコードの `status` を更新(`有効` ⇄ `無効`)。全員に効く |
| 編集できない | **ローカル無効化**に切り替え。トーストで「このブラウザでのみ無効にしました」と明示 |
| `public` を `private` に落とす / 逆 | 影響範囲バッジから変更。`public` 化は公開権限が必要(→ 08) |

- レコード編集の可否は `getRecordACLEvaluate` で判定し、一覧取得時にまとめて解決してキャッシュする。
  このAPIは**1リクエストにつきレコードID最大100件**で、実行には対象アプリのレコード閲覧または追加権限が要る。
  本プラグインの実行上限も100件なので、一覧1回につきこのAPIも1回で足りる
  ([APIを実行したユーザーのレコードのアクセス権の設定を取得する](https://cybozu.dev/ja/kintone/docs/rest-api/records/evaluate-record-permissions/))。
- **このAPIはレコード単位(`viewable` / `editable` / `deletable`)に加えて、フィールド単位の
  `viewable` / `editable` も返す。** これを使い分ける。

| UI要素 | 見る権限 |
| --- | --- |
| 有効スイッチ | `record.editable` **かつ** `fields[statusFieldCode].editable` |
| 影響範囲バッジの変更 | 上記 + `fields[scopeFieldCode].editable` + `canPublish`(public化のとき) |
| ドラッグハンドル | `record.editable` かつ `fields[orderFieldCode].editable` |
| 詳細のコード保存 | `record.editable` かつ `fields[codeFieldCode].editable` |
| 権限スイッチ | `record.editable` かつ `fields[permissionsFieldCode].editable` |
| 通信先の編集 | `record.editable` かつ `fields[externalUrlsFieldCode].editable` |
| 削除ボタン | `record.deletable` |

  レコードとしては編集できてもフィールドのアクセス権で `scope` や `code` だけが読み取り専用、という構成は
  [08-security.md](./08-security.md) が**推奨している設定そのもの**である。レコード単位だけで判定すると、
  「押せるのに必ず失敗するスイッチ」を推奨構成の環境で出すことになる。
- メンテナンスモード中は全て `false` が返る。「権限がありません」ではなく「いま操作できません」と表示する。
- 切り替え後の反映:
  - **CSS**: `<style>` の追加/削除で即時反映。
  - **JS**: 有効化は即時実行**しない**。「再読み込みで有効になります」と表示し、再読み込みボタンを出す。無効化は「次回以降適用されません」と表示(すでに走ったコードは取り消せない)。
  - この非対称性はユーザーが必ず混乱するので、**文言で毎回説明する**。

### 詳細(コード表示)

- 等幅フォント + 行番号のテキストエリア。構文ハイライトはv1では入れない(バンドルサイズ優先)。
- 上部に: タイトル / 説明 / 影響範囲 / 実行順 / 適用画面 / 生成モデル / 更新者・更新日時。
- ボタン: `保存` `AIに相談` `複製` `削除`。CSSだけ `プレビュー` を表示し、JSには表示しない。
- `AIに相談` はチャットタブへ遷移し、そのアセットの `read_asset` 承認カードを最初に表示する。
- 手動編集も許可する。**AIを介さずに直せる逃げ道は必ず残す**。

### 権限(カスタマイズ単位)

仕様と限界は [13-launch-gate-and-permissions.md](./13-launch-gate-and-permissions.md) 3章。

```text
┌ 権限 ─────────────────────────────────────────────┐
│ 読み取り(GET)              常に許可                │
│ 追加(POST)                 ─○                      │
│ 更新(PUT)                  ●─   12行目, 40行目     │
│ 削除(DELETE)               ─○                      │
│ 外部通信   (禁止)(●指定先のみ)(すべて)              │
│   https://zipcloud.ibsnet.co.jp/api/   ✓ 22行目で使用 │
│   https://fonts.googleapis.com         ⚠ 使用箇所なし │
│   [＋ 通信先を追加]                                  │
│   コードが使う未登録の送信先: https://api.example.com (31行目) [追加] │
│ 制限なし                   ─○   ⚠ 使用中の書き方: 8行目 window.kintone │
│ ⓘ 権限は誤操作を防ぐ安全装置です。悪意あるコードを止める仕組みではありません │
└──────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
| --- | --- |
| 使用箇所 | `detectCapabilityUsage` が見つけた、その権限を使う行番号を並べる。クリックでコード表示の該当行へ移動 |
| 付与 | 確認ダイアログで「このコードは12行目・40行目でレコードを更新します」を示してから保存する。使っていない権限の付与には「このコードは使っていません」を出す |
| 判定できない呼び出し | メソッドが変数の `kintone.api` 呼び出しは「実行時に判定します」と表示する(実行時にはファサードが止める) |
| 取り消し | 確認なしで保存してよい(安全側)。このタブでは次のAPI呼び出しから止まり、他の利用者は次の画面読み込みから止まる |
| 制限なし | 迂回パターンがあるJSを動かすための権限。付与時は迂回箇所を赤字で示し、「ほかの権限設定は意味を持たなくなります」と明示する |
| 外部通信の切り替え | 「禁止 / 指定先のみ / すべて」の3択。既定は禁止 |
| 通信先の一覧 | 1行1パターン。各行に正規化後の表示、`kintone.proxy` / CSSでの使用箇所、無効なパターンなら赤字の理由(クエリを含む、ワイルドカード、未対応スキームなど)を出す。`http:` は「暗号化されない通信です」と警告 |
| 未登録の送信先 | コードがリテラルで使っているのに一覧に無い送信先を、行番号付きで出す。「追加」は確認ダイアログを経て一覧へ入れる。URLを組み立てているため判定できない呼び出しは「実行時に判定します」と出す |
| コード内の外部URL | JSの文字列リテラルにある外部URL(`<a href>` など)を参考情報として出す。**実行時には制御されない**ことを明記する |
| 「すべて」への切り替え | 「このカスタマイズは、あなたが読めるデータを任意の送信先へ送れるようになります」を確認させる。指定先の一覧は消さずに残し、「指定先のみ」へ戻したときに使う |
| 活性 | 上の表の「権限スイッチ」の規則(通信先の編集は `fields[externalUrlsFieldCode].editable` も見る)。publicアセットは一般ユーザーには読み取り専用で表示する |

### 拒否の記録

ファサードが止めた操作は、アセットごとに一覧の ⚠ と詳細画面へ出す。

```text
⚠ 「保存時に在庫を引き当てる」が レコード更新(PUT /k/v1/record.json)を試みましたが、
  許可されていないため止めました。 14:03  [権限を確認]
```

- 同じ内容はまとめて件数表示にする(1ページの表示中に何十件も積まない)。
- `[権限を確認]` は、権限スイッチを変更できる人にだけ出し、詳細画面の該当スイッチへ移動する。**その場では付与しない**
  (拒否をきっかけにコードを見ずに許可する流れを作らない)。

## 6. チャットパネル

```
┌──────────────────────────────────────────────────┐
│ チャット                        [新しい会話] [×] │
├──────────────────────────────────────────────────┤
│ 🧑 一覧でステータスが失注の行をグレーにして        │
│                                                  │
│ 🤖 アプリのフィールドを確認します                 │
│    ┌────────────────────────────────────────┐   │
│    │ 🔧 get_form_fields                  ✓  │   │ ← ツール実行カード(折りたたみ)
│    └────────────────────────────────────────┘   │
│    ┌────────────────────────────────────────┐   │
│    │ 🔧 query_dom  ".recordlist-row-gaia" ✓ │   │
│    └────────────────────────────────────────┘   │
│    CSSを作りました。プレビューで確認できます。     │
│    ┌────────────────────────────────────────┐   │
│    │ 📝 write_asset (新規 / CSS)             │   │ ← 承認待ちカード
│    │ タイトル: 失注行をグレーアウト           │   │
│    │ ```css … ```                            │   │
│    │ 影響範囲: [自分だけ ▾]                  │   │
│    │        [プレビュー] [却下] [登録する]    │   │
│    └────────────────────────────────────────┘   │
├──────────────────────────────────────────────────┤
│ [メッセージを入力…                    ] [送信]   │
└──────────────────────────────────────────────────┘
```

### 仕様

| 項目 | 内容 |
| --- | --- |
| 送信 | `Enter` で送信 / `Shift+Enter` で改行(既存プラグインの慣習に合わせる) |
| 応答の表示 | **ストリーミングは使えない**(kintoneプロキシの制約 → [07b](./07b-ai-providers.md) 3章)。1往復ぶんの応答がまとまって表示される |
| 生成中の表示 | 「考えています… 12秒」と経過秒数を出す。ツールを実行した往復ごとにカードが積まれるので、それ自体が進捗になる |
| ツールカード | 既定は折りたたみ。クリックで引数と結果(整形済みJSON、長い場合は先頭2KB)を表示 |
| 承認カード | 書き込み系ツールで表示。差分(既存がある場合)、影響範囲の選択、プレビュー、承認/却下 |
| 読み取り承認 | レコード値・既存コードを送る前に、対象field/asset、件数、byte数、送信先を表示。レコード値は承認前に取得しない |
| 中断 | 生成中は送信ボタンが「停止」に変わる。`AbortController` で待機を止めるが、課金停止は保証しない |
| 会話の保存 | **プラグイン設定で有効なときだけ**、削減済みログを保存する。DOM・レコード・コードの生のツール出力は保存しない |
| 会話の復元 | private詳細の「AIに相談」から保存済み会話を復元できる。publicまたは保存なしは、最新コードを読み直した新規会話として始める |
| 保存中であることの明示 | 保存が有効なとき、パネル上部に「この会話はレコードに保存されます」と常時表示する |
| コンテキスト表示 | パネル上部に「対象: アプリ名 / 詳細画面」と、レコード送信の有無を常に表示する |
| エラー | AI呼び出しの失敗は、原因(認証 / レート制限 / タイムアウト / その他)を切り分けて日本語で表示 |

### プレビュー

| 種別 | 挙動 |
| --- | --- |
| CSS | 一時 `<style>` を適用。パネルに「プレビュー中」バーと「解除」ボタンを出す。パネル終了・画面遷移でも自動解除 |
| JS | v1ではプレビューしない。`無効` で保存してレビュー後に有効化し、再読み込みする |

JSは取り消し不能で無限ループも停止できないため、「プレビュー」という名前で安全に見せない。

## 7. 権限がない場合の表示

| 状況 | 表示 |
| --- | --- |
| プラグイン未設定 | ランチャーを出さない(完全に無表示) |
| 設定不備(必須フィールド未設定) | アプリ管理権限がある人にだけランチャーを出し、「プラグインの設定が完了していません」と案内 |
| チャット権限なし | メニューに「チャット」を出さない |
| 公開権限なし | 影響範囲の「全員」を選択不可にし、理由をツールチップで説明 |
| アセットが0件 | 一覧に空状態(`@repo/ui` の `EmptyState`)と「チャットで作ってみる」導線 |

## 8. 通知

`notistack` を使う(既存プラグインと同じ)。

| 種類 | 例 |
| --- | --- |
| success | 「アセットを登録しました」 |
| info | 「このブラウザでのみ無効にしました」 |
| warning | 「カスタマイズの読み込みが間に合いませんでした。再読み込みしてください」「『◯◯』の許可されていない操作を止めました」 |
| error | 「アセット『◯◯』の実行に失敗しました」 |

## 9. 国際化

`src/lib/i18n.ts` で `@repo/utils` の `commonUi` をマージして定義する。v1は `ja` / `en` を用意し、
未定義言語は `en` にフォールバックする。**UI文言をコンポーネントに直書きしない**。

## 10. ビジュアルと状態の規約

- `@repo/ui` とMUIの既存primitiveを優先し、独自のclick可能な `div` を作らない。
- 色はMUI theme / リポジトリのsemantic tokenから取得する。hex、rgb、独自gradientを仕様として固定しない。
- kintone側のlight/dark表示と高コントラストで、surface / text / border / focus ringを確認する。
- error / warning / success / disabled / scopeは色だけで区別せず、アイコンと可視テキストを併記する。
- hover、active、disabled、focus-visible、loading、empty、error、approval-pending、safe-modeをStorybook相当のfixtureで確認する。
- focus ringを消さない。起動ボタンとドラッグハンドルは44px以上の操作領域を確保する。
- 375 / 768 / 1024 / 1440pxで、パネル、diff、長いコード、英語文言、200% zoomのoverflowを確認する。
- カードを入れ子にしすぎず、余白と見出しで階層を作る。強いshadowや彩度の高い面は承認・警告の意味付けに使わない。
