# 04. アセット管理アプリ

アセット(JS/CSS)を保存するkintoneアプリの仕様。プラグイン設定でこのアプリとフィールドを指定する。

## 1. 設計方針

- **1レコード = 1アセット**。ファイル添付ではなく文字列フィールドに直接コードを入れる。
  - 理由: 一覧取得が1回のAPIで済む / 全文検索が効く / レコード履歴に差分が残る / ダウンロードのラウンドトリップが不要。
  - kintoneフィールドの上限とは別に、本プラグイン自身の取得・実行の上限を設ける(→ 5)。
- 対象アプリごとにアプリを分けず、**1つの管理アプリで全アプリのアセットを持つ**。
  `(targetSpaceId, targetAppId)` で絞る。ゲストスペース間ではアプリIDが衝突しうるため、ID単体で識別しない。
- **ただしゲストスペースは例外で、管理アプリを共有できない。** ゲストユーザーは所属するゲストスペースの外にある
  アプリへアクセスできないため、ゲストスペース上の対象アプリから通常スペースの管理アプリを読むことはできない。
  したがって**ゲストスペースごとに管理アプリを1つ用意し、そのスペース内のアプリだけを担当させる**。
  `assetAppSpaceId` はこのために存在する。「1つの管理アプリで全社ぶん」が成り立つのは通常スペースの範囲内だけである。
  設定画面では `assetAppSpaceId` と対象アプリのゲストスペースIDが食い違うときに警告する。
- 通常UIとAIツールは、`public` とログインユーザーが作成した `private` だけを取得する。
  管理者の監査は管理アプリの標準一覧で行い、一般利用者の実行UIへ他人のprivateコードを出さない。

## 2. フィールド定義

| # | フィールド名(例) | フィールドコード(例) | 型 | 必須 | 設定 |
| --- | --- | --- | --- | --- | --- |
| 1 | タイトル | `title` | 文字列(1行) | ○ | 必須入力 |
| 2 | 対象アプリID | `targetAppId` | 数値 | ○ | 必須入力 / 小数点以下0桁 / 桁区切り無し |
| 3 | 対象ゲストスペースID | `targetSpaceId` | 数値 | ○ | 通常スペースは `0` / 小数点以下0桁 / 桁区切り無し |
| 4 | 種別 | `kind` | ドロップダウン | ○ | 選択肢: `JavaScript`, `CSS` / 必須 |
| 5 | 影響範囲 | `scope` | ドロップダウン | ○ | 選択肢: `自分だけ`, `全員` / 既定 `自分だけ` / 必須 |
| 6 | 状態 | `status` | ドロップダウン | ○ | 選択肢: `有効`, `無効` / 既定 `無効` / 必須 |
| 7 | 所有者 | 作成者フィールド | 作成者 | ○ | kintone標準フィールド。変更不能 |
| 8 | コード | `code` | 文字列(複数行) | ○ | - |
| 9 | 実行順 | `order` | 数値 | - | 既定 `100` / 小数点以下0桁 |
| 10 | 適用画面 | `screens` | チェックボックス | - | 選択肢: `一覧`, `詳細`, `追加`, `編集` / 既定は全選択 |
| 11 | 説明 | `description` | 文字列(複数行) | - | 何のためのコードかをAIに書かせる |
| 12 | 対話ログ | `conversation` | 文字列(複数行) | - | JSON。**設定が有効なときだけ、削減済みログを書き込む** |
| 13 | 生成モデル | `model` | 文字列(1行) | - | 監査用 |
| 14 | 権限 | `permissions` | チェックボックス | ○ | 選択肢: `追加(POST)`, `更新(PUT)`, `削除(DELETE)`, `外部通信(指定先のみ)`, `外部通信(すべて)`, `制限なし` / **初期値は全て未選択**。未選択 = 読み取りのみ(→ [13](./13-launch-gate-and-permissions.md) 3章) |
| 15 | 通信先 | `externalUrls` | 文字列(複数行) | - | 外部通信を許可する送信先。1行1パターン、`#` 行はコメント。書き方は 13 の 3-3-2章 |

> フィールドコードは自由。プラグイン設定で対応付けるため、既存アプリを流用してもよい。
> ただし**型は表の通りである必要がある**(設定画面で検証する)。

> 「権限」「通信先」にはフィールドアクセス権を設定しない。kintoneのフィールドアクセス権はレコードの値で条件を変えられないため、
> publicアセットの権限はレコードアクセス権(publicは管理者だけ編集可)で守る(→ [08-security.md](./08-security.md) 2-5)。

### 一覧ビューの推奨設定

| ビュー | 用途 | 設定 |
| --- | --- | --- |
| 既定の一覧 | 運用・棚卸し | 表示フィールド: 対象アプリID / 種別 / タイトル / 影響範囲 / 状態 / 所有者 / 更新日時。ソート: `targetAppId asc, order asc` |
| 無効なもの | 事故調査 | フィルタ: 状態 = 無効 |
| 全員公開のみ | 棚卸し | フィルタ: 影響範囲 = 全員 |

## 3. 取得クエリ

`src/lib/asset-query.ts`(純粋関数)で組み立て、単体テストする。

### 3-1. 起動時(適用対象のみ)

```
targetSpaceId = 0
  and targetAppId = 42
  and status in ("有効")
  and (scope in ("全員") or (scope in ("自分だけ") and owner in (LOGINUSER())))
order by order asc, $id asc
limit 101
```

- `LOGINUSER()` はkintoneのクエリ関数。ログインユーザーで絞る処理をサーバー側に寄せられる。
- 実行上限は1対象アプリ100件。`limit 101` で超過を検出し、超えた場合は動的アセットを実行せず、
  ランチャーに管理アプリの整理を求めるエラーを表示する。一部だけ実行すると依存順が壊れるため、切り捨て実行しない。
- 選択肢の値はプラグイン設定から取るため、**必ずエスケープする**(`"` と `\` )。テストケースを用意すること。

### 3-2. パネルを開いたとき(無効なものも含む全件)

```
targetSpaceId = 0
  and targetAppId = 42
  and (scope in ("全員") or (scope in ("自分だけ") and owner in (LOGINUSER())))
order by order asc, $id asc
limit 101
```

起動時は「有効なもの」だけを取り、パネルを開いて初めて全件を取り直す。初期表示のペイロードを小さく保つため。

### 3-3. 取得フィールドの限定

`getRecords` の `fields` に、プラグイン設定で対応付けたフィールドコード + `$id` + `$revision` + `更新日時` + `更新者` のみを指定する。
**起動時のクエリでは `conversation`(対話ログ)を取得しない。** 長大になりがちで、実行には不要なため。
対話ログはチャットで会話を再開するときにだけ、そのレコード1件を指定して取得する。

## 4. レコード ⇄ Asset の変換

```ts
// src/schema/asset.ts
export type AssetKind = 'js' | 'css';
export type AssetScope = 'private' | 'public';
export type AssetScreen = 'index' | 'detail' | 'create' | 'edit';
export type AssetPermission =
  | 'post' | 'put' | 'delete'
  | 'external-listed' | 'external-all'
  | 'unrestricted';

export type Asset = {
  /** レコードID(文字列) */
  id: string;
  /** 楽観ロック用 */
  revision: string;
  title: string;
  targetAppId: string;
  targetSpaceId: string;
  kind: AssetKind;
  scope: AssetScope;
  enabled: boolean;
  /** 所有者のログイン名。取得できない場合は空文字 */
  ownerCode: string;
  code: string;
  order: number;
  /** 空配列は「全画面」を意味する */
  screens: AssetScreen[];
  /** 付与済みの権限。空配列は読み取りのみ */
  permissions: AssetPermission[];
  /** 外部通信の通信先パターン(正規化済み・有効なものだけ) */
  externalUrls: string[];
  /** 無効として除外した通信先の行と理由(UI表示用) */
  invalidExternalUrls: { line: number; raw: string; reason: string }[];
  description: string;
  model: string;
  updatedAt: string;
  updatedByCode: string;
};
```

`src/lib/asset-mapper.ts` に `toAsset(record, common): Asset | null` と `toRecordValue(asset, common)` を置く。

**変換時の防御(すべてテストを書く)**

| 入力 | 期待する挙動 |
| --- | --- |
| 必須フィールドが欠けている | `null` を返し、コンソールに警告。**実行対象から除外する**(落とさない) |
| `kind` が既知の値でない | `null`(実行しない) |
| `scope` が既知の値でない | `private` として扱う(**安全側**: 意図せず全員へ配られるのを防ぐ) |
| `status` が既知の値でない | `false`(無効)として扱う(安全側) |
| `order` が数値でない / 空 | `100` |
| `screens` が空配列 | 全画面に適用 |
| `owner` が未設定 | `ownerCode: ''`。`private` なら誰にも適用されない |
| `code` が空文字 | 実行しない(一覧には出す) |
| `permissions` に未知の値がある | その値を無視する(安全側。権限が増える方向に倒さない) |
| `permissions` フィールドが取得できない | 空配列(読み取りのみ)として扱う |
| `external-listed` と `external-all` が両方ある | `external-all` を外す(狭いほうへ倒す)。一覧に設定不備を出す |
| 通信先に無効な行がある | その行だけ除外し、`invalidExternalUrls` に理由を残す。有効な行は使う |

## 5. コード量の上限

kintoneの「文字列(複数行)」フィールドには、実用上の障害になるような文字数上限はない。
コミュニティの検証では**少なくとも約524万文字(5,242,880文字)が保存できる**ことが確認されており、
公式に65,535文字といった上限が定められているわけではない([検証記事](https://community.cybozu.dev/t/topic/10454))。

> ※ 65,535文字はスペース/スレッドの本文などに出てくる値で、文字列(複数行)フィールドの上限ではない。

保存先が許容しても、REST応答、AI入力、構文解析と評価の時間を無制限にはしない。`TextEncoder` で測ったUTF-8 byte数に
次のv1固定上限を置き、P-1の実測後に定数を調整する。

| 対象 | 上限 | 超過時 |
| --- | --- | --- |
| 1アセットのコード | 128 KiB | AIツールからの保存を拒否。管理アプリから入った既存レコードは実行対象外 |
| 1対象アプリの有効コード合計 | 2 MiB | その取得結果を実行せず、管理者向けエラー |
| 対話ログ1件 | 128 KiB | 古いturnから削減し、収まらなければ保存せず警告 |

コード本文と対話ログは同じREST取得に混ぜない。上限超過を「先頭だけ実行」で処理せず、状態を明示して安全側へ倒す。

AIには**システムプロンプトで「1アセットは200行程度までに収め、機能ごとに分割する」よう指示**する(→ 07)。
これは容量の制約ではなく、**レビューしやすさと再利用しやすさのため**である。

## 5-2. 対話ログ(`conversation`)

**プラグイン設定 `savesConversation` が有効で、かつ `conversationFieldCode` が設定されている場合にのみ保存する。**
どちらか一方でも欠けていれば、フィールドには一切書き込まない。

### 保存する内容

保存容量ではなく、機密性・鮮度・監査可能性を基準にする。privateでは**ユーザー発言、AI本文、ツール名、入力、
結果の要約、承認判断**を保存する。publicでは閲覧者が増えるため本文を保存せず、provider/model、tool名、
結果hash、承認者・判断、生成コードhashだけのaudit modeにする。どちらもツールの生出力は保存しない。

```jsonc
{
  "schemaVersion": 1,
  "mode": "private-full",
  "provider": "anthropic",
  "model": "configured-model-id",
  "savedAt": "2026-09-08T09:30:00+09:00",
  "turns": [
    { "role": "user", "content": "一覧で失注の行をグレーにして" },
    { "role": "assistant", "content": "フィールドを確認します",
      "toolCalls": [{ "id": "t1", "name": "get_form_fields", "args": {} }] },
    { "role": "tool", "toolCallId": "t1", "name": "get_form_fields",
      "result": { "status": "success", "summary": "12 fields", "sha256": "…" } },
    { "role": "assistant", "content": "CSSを作りました", "toolCalls": [/* write_asset */] }
  ]
}
```

- `get_record_sample`、`query_dom`、`read_asset` の生出力は保存しない。再開時は最新データをツールで取り直す。
- `write_asset` のコード本文はアセット本体にあるため、ログにはhash・文字数・diff要約だけを保存する。
- privateからpublicへ変更するときは、承認後・更新前に本文をaudit modeへ不可逆に削減する。publicからprivateへ戻しても復元しない。
- 各文字列とログ全体に128KiBの上限を設け、超過時は古いturnから削る。削除件数を `compaction` に記録する。
- AIへ送る履歴も同じ削減済みログを基礎にし、必要な最新データだけを再取得する(→ [07-ai-tools.md](./07-ai-tools.md) 6章)。
- **保存のタイミングは「その発言に対するAgentループが完全に終わったとき」**。`write_asset` の `execute` の中では保存しない。
  execute時点ではAIの締めの発言(「登録しました。○○に注意してください」)がまだ生成されておらず、
  会話の末尾が欠けたログが残るためである。ループ終了時に、その発言中に書き込んだアセットIDを対象として
  `conversation` フィールドだけを更新する。
- この更新はレコードのrevisionを1つ進め、更新履歴にもう1件残る。**これは仕様として受け入れる**
  (コード差分の履歴と対話ログの履歴を1トランザクションにまとめる手段が無いため)。
  管理アプリの履歴を読む人が混乱しないよう、対話ログ更新であることが分かる状態にしておく。
- 保存に失敗しても**アセットの登録は成功として扱う**。ログの保存失敗でコードの登録まで巻き戻さない。
  失敗はトーストで知らせるだけにとどめる。

### 注意

- privateの対話ログには**ユーザーが入力した業務上の文脈がそのまま残る**。そのprivateレコードを読める人は内容も読める。
  既定をオフにしているのはこのため。有効化するときは設定画面でも警告する(→ [03-plugin-config.md](./03-plugin-config.md))。
- publicは本文を持たないaudit modeなので、会話の続きから再開できない。最新アセットを読み直した新規会話として扱う。
- `sendsRecordToAi` が有効でも、レコード値の生データは対話ログへ保存しない。

## 6. アプリの作り方

### v1: 手動 + テンプレート

以下の手順を `apps/ai-customize/docs/` から参照できる形で配布する(実装時に `templates/asset-app.json` を追加)。

1. kintoneで新規アプリを作成
2. 上の表の通りにフィールドを配置
3. アプリのアクセス権を設定(→ [08-security.md](./08-security.md))
4. 対象アプリに ai-customize プラグインを追加し、設定画面で管理アプリとフィールドを対応付ける

### 自動作成は行わない

設定画面のボタンから管理アプリを自動生成する案は**採らない**(方針決定済み)。
代わりに、手順書と `docs/templates/asset-app.json`(フィールド定義)を配布し、設定画面の検証で設定ミスを拾う。

## 7. 運用上の注意

- **管理アプリを消す / フィールドを消す**と、全対象アプリのアセットが動かなくなる。設定画面と操作画面の両方で「アセットを取得できません」と明示する(黙って何もしないのが最悪)。
- 対象アプリを削除しても管理アプリのレコードは残る。棚卸し用に「対象アプリIDが存在しないレコード」を洗い出す一覧を作っておくとよい。
- アセット管理アプリ自身には ai-customize プラグインを入れないこと(自分のコードで自分の管理画面を壊せてしまう)。設定画面で `assetAppId === 現在のアプリID` を検出したら警告する。
