## 30秒でわかる概要

1. 管理者はプラグイン設定で「**アセット管理アプリ**」(JS/CSSを保存するkintoneアプリ)とフィールドの対応を指定する。
2. 利用者がアプリを開くと、画面右下に低い不透明度のランチャーボタンが常時表示される。
3. ランチャーから **JS / CSS / チャット** の3メニューを開ける。
   - **JS / CSS**: このアプリに登録済みのコードの一覧。タイトルと影響範囲(自分だけ / 全員)と権限(更新・削除など)が並び、スイッチで有効・無効や権限を切り替えられる。
   - **チャット**: AIと会話しながらコードを作る。AIは定義済みfunction(ツール)を通じて、アプリのスキーマ取得・既存コードの読み込み・登録・更新を行う。
4. 登録されたコードは、次回以降そのアプリを開いたときに自動で適用される。

## 最重要の設計上の論点

実装に入る前に、少なくとも次の5つは目を通してほしい。

1. **任意のJavaScriptを実行する仕組みである**(→ [08-security.md](./08-security.md))
   本プラグインは、kintoneアプリのレコードに保存された文字列をブラウザ上で実行する。これは「JavaScriptカスタマイズの実行権限を、アプリのレコード編集権限に委譲する」ことに等しい。権限設計と監査を先に固めないと出してはいけない。
2. **kintoneイベントに間に合わせる方法**(→ [05-runtime.md](./05-runtime.md)、[13](./13-launch-gate-and-permissions.md))
   アセットはREST API経由の非同期取得だが、同期でなければならないのはハンドラの**登録**だけである。
   showハンドラを同期登録し、初回showでPromiseを返して取得完了まで保留する(**起動ゲート**)。
   初回から通常のJSカスタマイズと同じタイミングで動き、コードを端末にキャッシュしない。
3. **壊れたJSからの復旧手段が必須**(→ [05-runtime.md](./05-runtime.md) セーフモード)
   利用者が自分でアプリを壊せてしまう以上、画面が真っ白になっても戻せる導線がないと運用できない。
4. **ストリーミングも中断も使えない**(→ [07b-ai-providers.md](./07b-ai-providers.md))
   全リクエストがkintoneのプロキシを通るため、逐次表示ができない。さらに `ketch` は `AbortSignal` を読まないため、
   停止ボタンで止まるのは待機だけで、生成と課金は続く。UIの体感設計と文言で補う必要がある。
5. **起動ゲートが全ユーザーの全画面のクリティカルパスにいる**(→ [05-runtime.md](./05-runtime.md))
   取得がshowより遅れたぶん、画面表示の完了が遅れる。タイムアウトを持ち、待ち時間をP-1で実測してから確定する。
6. **カスタマイズ単位の権限は安全装置であって檻ではない**(→ [13](./13-launch-gate-and-permissions.md) 3章、[08](./08-security.md) 2-5)
   読み取りは常時、追加・更新・削除・外部通信はアセットごとに許可制。外部通信は送信先URLを指定するか、すべて許可するかを選べる。
   AIの誤りは止められるが、悪意ある迂回は止められない。

## 決まっていること

| 論点 | 決定 |
| --- | --- |
| AIの実装 | **BYOK + AI SDK 7**(ADR-40)。`ToolLoopAgent` と公式provider packagesをcustom proxy fetchで使う |
| 使用モデル | 固定リストを持たず、自由入力 + プロバイダごとの候補補完。「接続を確認」でツール対応を実測 |
| 実行順 | ドラッグ&ドロップで並べ替え(`@dnd-kit`) |
| 対話ログ | プラグイン設定で有効にしたときだけレコードへ保存。既定オフ |
| 管理アプリの自動作成 | 行わない。テンプレート配布 + 設定画面の検証で代替 |
| 提供形態 | 導入企業の判断に委ねる。こちらは判断材料([08-security.md](./08-security.md))を揃える |
| 書き込み | 全て人間の承認必須。v1は自動承認とJSプレビューを提供しない |
| 承認の再開 | AI SDKの `tool-approval-response` に任せる。ツール実行を自前で組まない |
| 接続確認 | 設定画面では `kintone.plugin.app.proxy` が使えない。入力中のキー + `kintone.proxy` で行う |
| APIキーの移行 | 実装しない。endpointが変わったら再入力させる |
| 依存の追加 | catalogへ新規登録しない(`catalogMode: strict`)。既存アプリと同じレンジを直書き |
| 起動方式 | 起動ゲート。同期キャッシュは廃止(ADR-33) |
| アセットのイベント購読 | 標準の `kintone.events.on`。アセットへ渡す `kintone` をファサードにする(ADR-34) |
| カスタマイズ単位の権限 | GETは常時許可。POST / PUT / DELETE / 外部通信は許可制で既定は禁止。実装後もスイッチで切り替え可(ADR-36) |
| 外部通信の範囲 | 禁止 / 指定先のみ(URLパターンを列挙) / すべて。AIは指定先のみ要求できる(ADR-39) |
| 実装開始 | [P-1実機スパイク](./12-preimplementation-review.md)の合格後 |

詳細と理由は [11-decisions.md](./11-decisions.md)。
