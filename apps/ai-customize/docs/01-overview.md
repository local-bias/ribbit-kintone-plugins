# 01. 概要 / 要件

## 1. コンセプト

kintoneの「あと一歩足りない」を埋めるために、これまでは用途ごとにプラグインを探し、導入し、設定してきた。
本プラグインは、その一歩を**その場でAIに作らせる**ことで、個別プラグインの導入自体を不要にすることを狙う。

> 「タブがほしい」「この列の色を変えたい」「保存前にチェックしたい」
> → チャットで頼むと、AIがJS/CSSを書いて、このアプリに登録・適用する。

## 2. 解決したい課題

| 課題 | 現状 | 本プラグインでの解決 |
| --- | --- | --- |
| 小さなカスタマイズのために毎回プラグインを探す | プラグイン導入 → 設定 → 検証。数時間〜数日 | チャットで数分 |
| JSカスタマイズはアプリ管理権限が必要 | 一般ユーザーは触れない | アセット管理アプリのレコード権限に委譲(→ 08) |
| 「自分の画面でだけ」という要求に応えられない | JSカスタマイズはアプリ全体に適用 | 影響範囲を「自分だけ / 全員」で選択 |
| 誰がいつ何を入れたか分からない | ファイルの差し替え履歴のみ | レコードの更新履歴・作成者としてkintoneに残る |
| 壊れたときに戻せない | 管理者に依頼してファイルを外す | スイッチで無効化 + セーフモード |

## 3. ユースケース

### UC-1: 一覧画面の見た目を整える(CSS / 自分だけ)
営業担当が一覧画面を開く → 右下ランチャー → チャット → 「ステータスが『失注』の行をグレーアウトして」
→ AIが `get_form_fields` と `query_dom` で一覧のDOM構造を調べ、CSSを生成 → プレビュー → 「自分だけ」で保存。

### UC-2: 入力チェックを足す(JS / 全員)
アプリ管理者が詳細画面で → 「金額が100万円を超えたら、保存時に確認ダイアログを出して」
→ AIが `app.record.edit.submit` を使うコードを生成 → 差分確認 → 「全員」で保存。
公開権限を持つユーザーのみ「全員」を選べる(→ 03, 08)。

### UC-3: 既存コードの手直し
JSメニューから既存アセットを開く → 「この処理、サブテーブルの行が0件のときにエラーになる」
→ AIが `read_asset` で現在のコードを読み、修正版を `write_asset` で更新。

### UC-4: 事故からの復旧
登録したJSでエラーが出て画面が操作できない → URLに `?ai-customize=off` を付けて再読み込み(セーフモード)
→ ランチャーは動くので、該当アセットのスイッチをオフにする。

## 4. スコープ

### v1 でやること

- プラグイン設定: アセット管理アプリとフィールドの対応付け、AIプロバイダ設定、権限設定
- デスクトップ画面(一覧・詳細・追加・編集)でのランチャー表示
- JS / CSS 一覧(タイトル・影響範囲・有効スイッチ・権限・コード閲覧)
- カスタマイズ単位の権限(読み取りは常時、追加・更新・削除・外部通信は許可制。外部通信は送信先URLの指定か、すべて許可かを選べる)
- AIチャット(ツール呼び出し、承認付き書き込み、プレビュー)
- アセットの読み込み・実行(CSS注入 / JS評価)、実行順制御、エラー隔離
- 影響範囲(自分だけ / 全員)と、ローカル無効化
- セーフモード

### v1 でやらないこと(明示的に非スコープ)

- モバイル画面対応(ランチャーは出さない。アセットの適用も行わない → v2)
- ポータル・スペースなど、アプリ外画面へのカスタマイズ
- アセット管理アプリの自動生成(手動作成。テンプレート定義は 04 に記載 → v1.1で自動生成を検討)
- コードの構文ハイライト付きエディタ(v1は等幅テキストエリア + 行番号のみ)
- JSのサンドボックス実行(技術的に不可能。リスクは 08 で権限により統制する)
- 生成コードのバージョン間diffのUI上での永続保存(kintoneのレコード履歴に委ねる)
- 複数アプリへの一括適用(アセットは1アプリに紐づく)

## 5. 想定ユーザーと権限

| ロール | できること |
| --- | --- |
| **アプリ管理者 / 公開許可ユーザー** | 「全員」スコープのアセットの作成・編集・有効化 |
| **一般ユーザー(チャット許可あり)** | 自分が作成した `private` アセットの作成・編集・有効化、適用対象アセットの閲覧、ローカル無効化 |
| **一般ユーザー(チャット許可なし)** | 適用対象アセットの閲覧とローカル無効化のみ。ランチャーの「チャット」は非表示 |
| **プラグイン未設定時** | 何も表示しない |

権限の判定ロジックは [08-security.md](./08-security.md) を参照。

## 6. 非機能要件

| 項目 | 目標 |
| --- | --- |
| 初期表示への影響 | 起動ゲートの待ち時間(取得がshowより遅れたぶん)をp95 150ms以下に抑える。タイムアウトを持ち、待ち時間と評価時間を計測する |
| バンドルサイズ | `desktop.js` 400KB(gzip前)以下を目標。チャットパネルとAI SDKは動的import |
| 対応ブラウザ | kintoneのサポートブラウザに準拠(Chrome / Edge / Firefox / Safari 最新版) |
| ゲストスペース | 対応(`detectGuestSpaceId()` を全API呼び出しに透過) |
| 多言語 | ja / en を用意。`@repo/utils` の `commonUi` + `useTranslations` に準拠 |
| アクセシビリティ | ランチャーはキーボード操作可能(Tabで到達、Enterで開く、Escで閉じる)、`aria-label` 必須 |

## 7. 用語

| 用語 | 意味 |
| --- | --- |
| **アセット (Asset)** | 登録された1件のJSまたはCSS。アセット管理アプリの1レコードに対応する |
| **アセット管理アプリ** | アセットを保存するkintoneアプリ。プラグイン設定で指定する |
| **対象アプリ (Target App)** | アセットが適用されるアプリ。プラグインを導入したアプリ |
| **対象座標** | `(ゲストスペースID, アプリID)` の組。通常スペースのゲストスペースIDは `0` |
| **影響範囲 (Scope)** | `private`(自分だけ) / `public`(全員) |
| **ローカル無効化 (Local Mute)** | レコードを変更せず、そのブラウザでだけアセットを止める仕組み |
| **セーフモード** | 全アセットの適用を止めて画面を開くモード |
| **ランチャー** | 画面右下に出るフローティングアイコンとメニュー |
| **ツール (Tool / Function)** | AIが呼び出せる、こちらで定義した関数 |

## 8. v1で明示する制約

- アセットの取得が起動ゲートのタイムアウトに間に合わなかったページでは、JSを実行しない(CSSだけ後から適用する)。保存前チェックも動かない。
- カスタマイズ単位の権限は、正規の書き方(`kintone.api` / `kintone.proxy`)による操作を止める安全装置である。`window.kintone` などの迂回は静的検出で実行を止めるが、検出をすり抜ける悪意あるコードは止められない。
- `new Function` の同期処理、無限ループ、メモリー大量消費は停止・隔離できない。復旧はセーフモードでの再読み込みに依存する。
- APIキー自体は操作画面へ返さないが、アセットJSは登録済みプロキシendpointを認証付きで利用できる。キーの費消やAIへの送信を完全には防げない。
- kintoneの非公開DOMクラスへ依存するコードは将来壊れうる。公開JavaScript APIで実現できる方法を優先する。
