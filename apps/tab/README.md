# 🗂️ kintone 垂直タブプラグイン

kintoneのレコード画面(追加・編集・詳細)に、スクロールへ追従する垂直方向のタブを追加するプラグインです。タブを切り替えることで、表示するフィールド・グループ・スペース・ラベル・罫線を出し分けられます。

[kintoneプラグイン一覧](https://ribbit.konomi.app/kintone-plugin/)

[ホームページ](https://konomi.app)

## ✨ 特徴

- レコード画面の左側にタブを表示し、スクロールしても画面内に固定表示されます
- タブごとに、以下の表示・非表示を設定できます
  - フィールド
  - グループフィールド
  - スペースフィールド(要素IDが設定されているもの)
  - ラベルフィールド(要素ID、または文言で指定)
  - 罫線(要素IDが設定されているものは個別に指定)
- それぞれ「指定したものだけ表示」「指定したものを非表示」の2通りから選択できます
- 表示できる要素が1つも無くなった行は、行ごと畳んで余白を残しません
- タブごとに、表示する画面(追加・編集・詳細)を選べます
- タブごとに、レコードの値・閲覧者(ユーザー/グループ/組織)・プロセス管理のステータスによる表示条件を設定できます
- 未入力の必須フィールドを含むタブに印を付け、保存時にそのタブへ自動で切り替えます
- 最後に選択していたタブを記憶します。`?tab=タブ名`をURLに付ければ、特定のタブを開いた状態でリンクを共有できます
- 上下矢印キー・Home・Endでタブを移動できます
- タブの幅は共通設定から変更できます(既定値190px、80〜480pxの範囲)
- タブが多い場合はタブ一覧内でスクロールできます。スクロールバーはホバー中(およびキーボード操作でフォーカスが当たっている間)のみ表示されます。ホバーの前後でタブの幅は変わりません
- 「一括編集」で、フォーム上の全要素とタブの対応を一覧しながらまとめて割り当てられます
- 設定情報はJSONファイルとしてエクスポート・インポートできます

> [!NOTE]
> モバイル表示では、レコード画面のレイアウトが異なるためタブは表示されません。

## 🔧 設定

1. アプリの設定画面から、このプラグインの設定を開きます
2. サイドバーの「+」ボタンで必要な数だけタブを追加し、タブ名を入力します
3. サイドバーの「共通設定」を開き、「一括編集」で各要素をどのタブに表示するか割り当てます
4. 必要に応じて、タブごとの設定画面から表示条件などを調整します
5. 「設定を保存」後、アプリを更新します

タブ名が未入力の設定はレコード画面に表示されません。

### 一括編集

共通設定の「一括編集」では、アプリのフォームに配置されている要素をレイアウト順に一覧し、
どのタブに表示するかをチェックボックスでまとめて割り当てられます。

タブごとの設定画面が「タブ→要素」の順で入力するのに対し、一括編集は「要素→タブ」の順で入力します。
編集しているのはどちらも同じ設定情報のため、一方での変更はもう一方にもそのまま反映されます。

| 表示 | 説明 |
| --- | --- |
| 列 | 設定されているタブ。列見出しのチェックボックスで、そのタブへ全要素をまとめて割り当て・解除できます |
| 行 | フォーム上の要素(フィールド・グループ・スペース・ラベル)。グループ内の要素は字下げして表示します |
| 要素IDが未設定の要素 | スペース・罫線・(文言も空の)ラベルは操作画面で特定できないため対象外です。行だけ表示し、要素IDの設定が必要なことを示します |

どのタブにも割り当てられていない要素があると、その件数を警告として表示します。
これらの要素は全てのタブで非表示になるため、意図しない設定漏れに気づけます。

要素IDが未設定で割り当てできない要素がある場合も、その件数を警告として表示します。
これらの要素は全てのタブで同じ扱い(`sub`なら常に表示・`add`なら常に非表示)になるため、
「非表示にしたはずの場所に余白が残る」原因になります。アプリのフォーム設定で要素IDを設定すると、
タブごとに割り当てられるようになります。

同じ文言のラベルがフォーム内に複数ある場合、操作画面ではそれらを区別できないため、
まとめて同じ設定が適用されます。一括編集では該当する行に警告アイコンを表示します。
ラベルに要素IDを設定すると、文言に関係なく1つずつ切り替えられます。

#### フォームに後から追加された要素の扱い

一括編集の割り当てをタブ設定へ書き戻すとき、各タブの表示方法を`add`と`sub`のどちらで
保存するかを選べます。現在フォーム上にある要素の見え方はどちらでも変わりませんが、
**この設定を保存した後にアプリへ追加された要素**の扱いだけが変わります。

| 選択 | 保存される表示方法 | 後から追加された要素 |
| --- | --- | --- |
| 全てのタブで表示する(既定値) | `sub`(指定したものを非表示) | 全てのタブに表示されます |
| 全てのタブで非表示にする | `add`(指定したものだけ表示) | どのタブにも表示されません |

既定値は「全てのタブで表示する」です。アプリにフィールドを追加するたびに
全てのタブの設定を見直す必要が無くなるため、運用上はこちらを推奨します。

なお、この画面で明示的にどのタブにも割り当てなかった要素は、どちらを選んでも
全てのタブで非表示になります。

### 共通設定

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| タブの幅 | 190px | レコード画面に表示するタブの幅。全てのタブに共通で適用されます(80〜480px) |
| 選択していたタブを記憶する | 有効 | 最後に選択していたタブを記憶し、次に同じアプリのレコードを開いたときに復元します |
| 未入力の必須フィールドをタブに表示する | 有効 | 未入力の必須フィールドを含むタブに印を付け、保存時にそのタブへ切り替えます |
| 空になった行を畳む | 有効 | 表示できる要素が1つも無くなった行を、行ごと畳みます |

設定値は`src/lib/plugin.ts`の`normalizeTabWidth`で描画時にも範囲内へ丸められるため、設定情報が壊れていてもレイアウトは破綻しません。

### 要素IDと表示の切り替え方

kintoneは2026年2月8日のアップデートで、ラベル・罫線にも要素IDを設定できるようになり、
`kintone.app.record.setFieldShown()`が要素IDを受け付けるようになりました。
本プラグインはこれに合わせて、要素IDを持つ要素を公式APIで切り替えます。

| 要素 | 識別方法 | 要素IDが未設定の場合 |
| --- | --- | --- |
| フィールド・グループ | フィールドコード | — |
| スペース | 要素ID | 切り替えできません(一括編集に警告を表示します) |
| ラベル | 要素ID(未設定の場合は文言) | 文言も空の場合は切り替えできません |
| 罫線 | 要素ID | 個別に指定できないため、`add`で全て非表示・`sub`で全て表示になります |

要素IDを設定していないアプリでも、従来どおり文言によるラベルの切り替えとDOMの操作で動作します。
要素IDを設定すると、文言の変更に影響されなくなるほか、非表示にした要素の枠ごと消えるため、
余白が残りにくくなります。

> [!NOTE]
> 「非表示にしていない場所に空白が残る」場合、要素IDが未設定のスペース・罫線・ラベルが
> 残っていることがほとんどです。一括編集の警告を確認してください。

### 空になった行の扱い

kintoneは行内の要素を全て非表示にしても行そのものを残すため、非表示にした分の余白が
残ることがあります。共通設定の「空になった行を畳む」を有効にすると、
表示できる要素が1つも無くなった行を行ごと畳みます(既定値は有効)。

判定はタブを切り替えるたびに行い、畳む前に必ず行の表示状態を戻してから測るため、
表示できる要素があるタブでは元に戻ります。サブテーブルの内側の行は対象外です。

### タブの表示条件

タブごとに、以下の条件を組み合わせて表示・非表示を切り替えられます。設定が空の項目は絞り込みを行いません。

| 条件 | 説明 |
| --- | --- |
| 画面 | タブを表示する画面(追加・編集・詳細)。1つも選択しない場合、そのタブはどこにも表示されません |
| レコードの値 | 選択したフィールドの値による条件。AND / ORで結合できます。編集中に値が変わると再評価されます |
| 閲覧者 | 表示対象のユーザー・グループ・組織。いずれかに該当すれば表示します |
| ステータス | プロセス管理のステータス。プロセス管理が無効なアプリでは設定できません |

> [!WARNING]
> 閲覧者による表示条件は**アクセス制御ではありません**。非表示にしたフィールドの値もブラウザからは取得できます。権限を制御したい場合は、kintoneのアクセス権を使用してください。
>
> 同じ理由で、閲覧者の所属情報が取得できなかった場合は「表示する」側に倒します。タブが消えて操作できなくなる事故を防ぐためです。

### URLでタブを指定する

`?tab=` にタブ名、または1始まりの番号を指定すると、そのタブを開いた状態でレコードを開けます。タブ名との完全一致を優先し、一致しなければ番号として解釈します。

```
https://example.cybozu.com/k/1/show?record=100&tab=見積
https://example.cybozu.com/k/1/show?record=100&tab=2
```

### 罫線の設定

要素IDが設定されている罫線は、他の要素と同じように「指定した罫線だけ表示」「指定した罫線を非表示」で
個別に切り替えられます。要素IDが未設定の罫線は個別に指定できないため、
「指定した罫線だけ表示」を選ぶと全て非表示に、「指定した罫線を非表示」を選ぶと全て表示になります
(設定情報のバージョン4以前の「罫線を全て非表示」は、前者へそのまま引き継がれます)。

### 未入力の必須フィールドの通知

kintoneは非表示のフィールドも必須チェックの対象にするため、必須フィールドが非表示のタブにあると「原因の見えない保存エラー」になります。この機能を有効にすると、

- 未入力の必須フィールドを含むタブに赤い印を表示します
- 保存操作時、未入力の必須フィールドが現在のタブに表示されていない場合、そのフィールドが見えるタブへ自動で切り替えます

判定を誤って保存を妨げることが無いよう、プラグイン側で保存を中断することはありません(未入力であれば、この後にkintone自身が保存を中断します)。

> [!NOTE]
> サブテーブル内のフィールドは行ごとの判定が必要なため、この機能の対象外です。

## 🛠️ 開発

```bash
# 型チェック
pnpm --filter tab check-types

# ユニットテスト
pnpm --filter tab test

# ローカル開発(JS・CSSの監視ビルドとkintoneへの自動アップロード)
pnpm --filter tab dev

# 本番ビルド(JS・CSS・署名済みZIPの生成)
pnpm --filter tab build
```

`pnpm --filter tab dev` には、リポジトリルートではなく`apps/tab/.env`にkintone環境の接続情報が必要です。

## 🎨 スタイリング方針(重要)

レコード画面へ差し込むタブUIのCSSは、`src/styles/desktop.css`の**カスケードレイヤー外(unlayered)**に手書きで定義しています。Tailwindのユーティリティクラス(`rad:`)は使用しません。

理由は、CSSのカスケードでは**レイヤーに属さない宣言が、レイヤー内の宣言より詳細度に関係なく常に優先される**ためです。kintone標準のCSSはレイヤーを使用していないため、`@layer utilities`へ入るTailwindのユーティリティは、kintoneのDOM(`#record-gaia`配下)へ描画した要素では軒並み打ち消されてしまいます。

このため、以下の方針で記述しています。

1. レイヤー外に定義し、kintone標準スタイルと同じ土俵に乗せる
2. プラグインが付与したルート要素のid(`#ribbit-tab-plugin-root`)を起点にし、詳細度を`(1,1,0)`以上に保つ(kintoneの`#record-gaia button`などに勝つため)
3. kintoneから継承・上書きされうるプロパティは全て明示的に指定する
4. 色は共通CSSの`--🐸*`変数を使いつつ、共通CSSが読み込まれない環境でも破綻しないようフォールバック値を併記する

ルート要素のidは`src/lib/constants.ts`の`PLUGIN_ROOT_ID`と`desktop.css`のセレクタで対になっているため、変更する場合は両方を更新してください。

> [!NOTE]
> `document.body`直下にポータルで描画するUI(他プラグインのDrawerなど)は、kintoneのセレクタが届かないため`rad:`ユーティリティで問題ありません。この制約はkintoneのDOM内へ差し込むUIに限った話です。

## 📦 設定情報のバージョン

| version | 概要 |
| --- | --- |
| 1 | 初期形式。設定を識別するIDを持たない |
| 2 | 設定の並び替えのため、各設定に`id`を追加 |
| 3 | 共通設定(`common`)を追加。`displayMode`を`fieldDisplayMode`へ改名し、未使用の`tabIcon`と配列内の空文字を除去 |
| 4 | タブの表示条件(画面・レコードの値・閲覧者・ステータス)と、共通設定の項目を追加 |
| 5 | 罫線を要素IDで個別に切り替えるため、`hidesHR`を`hrDisplayMode`・`hrs`へ移行 |

`common`へ後から追加された項目(`tabWidth`・`newElementPolicy`など)は、保存済みの設定情報に無くても`migrateConfig`が既定値で補完するため、バージョンを上げる必要はありません。

保存済みの設定は`src/lib/plugin.ts`の`migrateConfig`によって、読み込み時に最新バージョンへ自動変換されます。
